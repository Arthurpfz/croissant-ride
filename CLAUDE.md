# Croissant Ride

Indoor smart-trainer app in the browser: one rider, switchable worlds, structured workouts, ERG control and FIT recording. No accounts and no backend: the rider posts the .FIT to Intervals.icu or Strava themselves.

- **Runs in:** Chrome/Edge (Web Bluetooth): desktop and Android. The layout adapts to phone/iPad/small laptops (`style.css` responsive section), but iOS browsers have no Web Bluetooth, so they can't pair sensors. Without `navigator.bluetooth` (Safari, Firefox, iOS) the start screen says so (`#no-bt`: open in Chrome/Edge; on iOS, Bluefy or another device).
- **Stack:** Vite + TypeScript, Three.js (the only runtime dependency). No framework; HUD is plain DOM.
- **Licence:** Apache-2.0. Ideas from AGPL/GPL projects (e.g. Auuki, qdomyos-zwift) are fine; their code is not. Fonts in `public/fonts/` (Geist, Geist Mono, Doto) are SIL OFL 1.1: keep `OFL.txt` beside them; only add fonts under OFL or a similar free licence.
- **Third-party notices:** `public/THIRD-PARTY-NOTICES.txt` (linked as "Licences" on the start screen) carries the licence of everything shipped in the app. Adding a runtime dependency or asset = add its notice there. Never add Garmin's FIT SDK (`@garmin/fitsdk`): its licence forbids redistributing it under an open-source licence; `src/fit.ts` is our own writer.
- **No look-alikes:** describe the app as an indoor trainer app, never a Zwift clone or "laid out like" another app; no other app's names, logos, colours or cue wording ("Ride by feel", not Zwift's "Ride On"). Naming a file format or a service to post to is fine.
- **Private setup notes** (deployment, hardware) go in `CLAUDE.local.md` (gitignored), never here.

## Commands
- Dev: `npx vite --port 5317` → `http://localhost:5317/?sim=1` (simulated sensors; `window.live` exposed for jumping around, e.g. `live.distance = 4700` = start of the Free Ride climb; `window.sim` fakes drops: `sim.mute.add('hr')` silences a metric, `sim.trainer.status = 'lost'` a disconnect, `sim.powerMeter.status = 'connected'` adds a low-reading PM; `sim.world.renderer.info.memory` / `sim.rec.recording()` to check skin switches; `sim.ride` = the ride engine: `mode`, `wT`, `offset`, `feel`, `spiral`, `target()`; `sim.clock.maxGap` = longest gap between ride ticks in ms, for checking a hidden tab: set it to 0, hide the tab, read it back)
- Build + type-check: `npm run build`

## Layout
- `src/trainer/` — **the trainer plug.** `trainer.ts` defines the one shape every trainer driver fills in (`TrainerDriver`: `service` that identifies the protocol, `setup(server, io, control)`, `setErg`, `setGrade`; readings go out through `io.power/cadence/hr`), picks the driver by the services the paired device has, deduplicates commands, logs them with `?debug=1` and drops them with `?observe=1`. **Add a trainer** = a new driver file + one entry in `drivers` (+ its service in `optionalServices` in `ble.ts` if it isn't there). Drivers: `ftms.ts` (Indoor Bike Data + Control Point: ERG `0x05`, SIM grade `0x11`, writes serialized; crank cadence from CPS/CSC when FTMS has none), `sim.ts` (`?sim=1`: near-perfect ERG, ~190 W on a gradient, nothing while the simulated rider isn't pedalling)
- `src/ble/` — `click.ts` (the "Remote control" chip: the original Zwift Click as a remote; ＋/− = target ±10 W. Zwift's own service (128-bit, or 16-bit 0xFC82), characteristics picked by property, plain `RideOn` greeting, button messages `0x37` = protobuf field 1 plus / 2 minus, 0 = pressed. A greeting reply carrying a key means an encrypted controller (Click v2, old firmware): refused on purpose, since getting around it breaks Zwift's terms. Facts from public protocol notes, never other projects' code. `?debug=1` logs the reply and packets; checked only against a mocked controller so far), `hr.ts` (HR + RR intervals → `live.rr`; a jump of >25 bpm counts only once the next reading confirms it, which drops the strap's junk values), `power.ts` (optional "Cadence" slot: a cadence sensor (CSC) or a crank PM → cadence source; PM power only without a trainer), `ble.ts` (picker, remembered devices, auto-reconnect)
- `workouts/` — the built-in sessions, one JSON file each (`name`, `who`, `steps` in % FTP: `{ min | sec, pct, free?, label? }`, `{ warmup: min }` 50→75 %, `{ cooldown: min }` 60→40 %, `{ repeat: n, steps, lastRecovery? }` whose first step is the work and carries "i of n"; a `pct` list gives each rep its own target; `{ ramp: { from, by, count } }` = 1-min steps, each `by` % higher). `ramp-test.json` is the **FTP test** (`"test": "ramp"`: 5 min at 46 %, then +6 % of FTP per minute from 52 %, 5 min cool-down). The engine ends the ramp when power stays under half the target for 10 s and jumps to the cool-down; the summary (`main.ts` `finish()`, `rec.bestMinute`) proposes FTP = 75 % of the best 60 s, with the 72–77 % range, and a button saves it. Steps scale with the rider's FTP on purpose: a faster ramp gives a higher best minute, so a fixed W step would skew light and strong riders differently. Adding a file adds a session (`import.meta.glob`, listed by file name; id = file name). Descriptive names only: no athlete, brand or band names.
- `src/workouts.ts` — loads `workouts/` into the `Workout` shape (+ Free Ride, built in). `free: true` = no ERG (sprints). `watts(pct, offset)` = every target in W: % FTP plus the rider's −/+ offset (10 W steps, ±150 W).
- `src/zwo.ts` — "＋ Import session": parses Zwift .zwo files (SteadyState, ranges → midpoint, Warmup/Ramp, Cooldown always ramps down, IntervalsT → reps, FreeRide/MaxEffort → free steps; `Cadence` (or the middle of `CadenceLow`–`CadenceHigh`, `CadenceResting` for an interval's recovery) → the step's `cad`, a target cadence shown as "82 / 90 rpm" in the HUD, in the step list and spoken in the cue, never enforced; `textevent`s become step `notes`, shown in the cue line for 10 s as 💬, offsets inside IntervalsT run across its reps) into the same `Workout` shape, stored in localStorage `imported-workouts`, listed first on the start screen with ✕ to remove; same name re-imported replaces it.
- `src/physics.ts` — virtual speed (CdA .32, Crr .005, weight+9kg)
- `worlds/` — world packs, data only (never code, so third-party packs can't run scripts). Adding a file/folder adds a pack (`import.meta.glob`); ids come from the file/folder name.
  - **Route ≠ skin.** A route (`worlds/routes/<id>.json`, or a folder `worlds/routes/<id>/route.json`) is the road: `line` (control points, x/z m: a closed loop, or with `oneWay` a road ridden to its end, turned round and ridden back), `elevation` (m, evenly spaced along the road, Catmull-Rom between points), optional `skin` (the route's default skin), `terrain` (real height grids: Uint16 decimetres in `.bin` files beside `route.json`, fetched on first use; a grid's `photo` is an aerial photo of the same rectangle, north up, ≤ 4096 px a side) and `scenery` (a JSON file beside it, loaded with the terrain: real `buildings` as rectangles, `places` along the road, a `tunnel` mouth, a `forest` bit mask on the finest grid; read through `sceneryOf` / `wooded` in `packs.ts`). Photos and scenery are facts about the place: each skin decides whether and how to draw them. It drives grade, ERG/SIM, physics and the FIT. A skin (`worlds/skins/<id>/skin.json`) is visuals only: `name`, `author`, `licence`, `assets`, `sky`, `fog`, `light`, `ground`, `road`, `rider` (suit, accent, skin, helmet, visor, shoes) + `bike` (frame, accent, parts, tyres, rims, `front`/`rear` wheel `deep`|`disc`, optional neon `glow` on the wheel edges), `props` placement rules, optional `bloom`. A skin can never change physics. `W` cycles the skins that fit the route (`skinsFor`): `dem` skins on a route with terrain, the others on flat routes; 🌍 is hidden when only one fits.
  - `valley-flat` = the default route, rolling within ±1 %, used by every workout incl. Free Ride. `galibier` = **Le Col**: the Col du Galibier from Valloire (18.2 km, 1,403 → 2,641 m, 6.8 %; IGN road + terrain, one-way; skins `le-col` (default) and `silver-col`), its own free-ride card (a workout's `route`). Rebuilt by `node scripts/galibier.mjs` (`--road` prints only the km-by-km check against the published climb; the trainer gets the real gradient, the D100 tops out at 6 %; `--scenery` keeps the road and heights on disk and rebuilds only the photos and scenery, which need `npm i --no-save sharp`). Its photos are IGN's ORTHO-EXPRESS flights (Savoie 2024, Hautes-Alpes 2025 recoloured to match: the yearly mosaic changes tone in patches), lifted because the flights are dark. Skins: `night-draft` is the default (`DEFAULT_SKIN`, start-screen backdrop and first ride; a rider's own pick wins). `default-valley` (original look), `cosmic-circuit` (glass road over a nebula, planets, small moons, asteroids, a light-ring gate per km, an occasional starfighter flyby, a rare armoured cube that fires at a moon, bloom), `night-draft` (monochrome night sketch: grey hill silhouettes, faint stars, road drawn as thin pen strokes, chalk rider, a rare shooting star; greys are pre-compensated for ACES tone mapping, so measure on screen when retuning). On the Galibier: `le-col` (the real place: the aerial photo on the ground, Valloire and the hamlets house by house, forest where it grows, place-name signs, the tunnel mouth, animals) and `silver-col` (**Silver Col**: a grey stone world after relief-shaded maps, lit from the north-west, faceted dark mountains, a dark road, white rider with a crust stripe, road furniture only: crust snow poles and km caps are its only colour).
  - Built-in vocabularies (procedural builders, extend in code): sky `gradient`|`nebula` (either takes `stars`), ground `valley`|`ridges` (flat ground + unlit hill silhouette rings)|`dem` (the route's real terrain: a 5 m strip along the road, then its grids, each sunk under the finer one; coloured by height, steepness and the way a slope faces, or with `photo` wearing the grids' aerial photos: half unlit since a photo has its own shadows, with a noise grain near the camera where a 3 m pixel would blur. The minimap then shows the photo too)|`none`, road `asphalt`|`glass`|`lines` (constant-pixel-width strokes), props `pines`|`planet`|`asteroids`|`gates`|`meteor` (shooting star every 1.5–4 min, right of the HUD; none under reduced motion)|`flyby` (a starfighter passes every 2–4 min)|`cube` (every 3–6 min, once a moon is in view: drifts in beside it, charges, fires at it, drifts out; click it to fire again; reduced motion = drift only). Le Col's: `village` (the scenery's buildings as chalets with windowed walls in one merged mesh, towers on churches and chapels, a boulangerie with a croissant sign near the start), `signs` (a French place-name panel before each of the scenery's places), `tunnel` (a concrete portal at the scenery's tunnel mouth), `markers` (a post per km: km to the summit + next km's gradient; summit car park and col sign, croissant on its back), `poles`, `walls` (where the ground drops), `snowbanks`, `chalk` (fans' words on the road), `cows`, `marmots` (dive into their burrow when you come close or click), `ibex` (rare), `paraglider`; `pines` takes `along` (around the road instead of a ring round the origin) + `maxSlope` + `forest` (only where the scenery has forest). `snowbanks` is no longer in a built-in skin (the photos are of a snowless September). Animated props set `userData.tick`, clickable ones `userData.click` (`scene.ts` raycasts canvas clicks). Placement uses a fixed seed, so a world is the same on every load. Licence must be CC0/CC-BY, or Licence Ouverte 2.0 for map data (IGN; never OpenStreetMap: ODbL is share-alike); no assets, names or recognisable designs from other games.
- `src/world/` — `packs.ts` loads + types the packs, `ROUTE`, `skinById()`. `route.ts` `Route` (pose, `gradeAt`, `elevAt`, `nearRoad`) + the active `route`. `skin.ts` builds a skin (sky, valley terrain, road styles) into one group with `dispose()`; `props.ts` builds a skin's props from `props/<type>.ts` (one file per prop type, default export, file name = type; adding a file adds the type); `kit.ts` shared helpers (`texture`, `lerp`, `still` for reduced motion, the `Tick` type); `noise.ts` value noise + seeded random; `rider.ts` low-poly time-trial rider (aero tuck, forearms on the pads, aero helmet with tail, tri suit) on a TT bike (deep front, disc rear, aero bars), designed per skin from `rider` + `bike`; shared rig with crank-driven IK legs, group named `rider`; `scene.ts` renderer, chase camera, shared fog/lights (reused: three.js caches per-light uniforms forever), bloom composer for skins with `bloom`, `show(route, skin)` and `switchSkin()` (fade via `#world.fading`, frees the old skin; no memory growth over 80 switches)
- `src/audio.ts` — cues: Web Audio beep 3 s before each step change + `speechSynthesis` summary of the next step ("240 watts, 10 minutes") in the best English voice found (premium/enhanced or Microsoft Natural > Google > classic macOS voices); mute in localStorage `audio-muted`
- `src/units.ts` — display units only (everything stored and recorded stays metric): imperial (lb, mph, mi, ft) by default for US English + an American time zone (many Europeans run en-US), metric elsewhere; the kg ⇄ lb switch beside Weight flips every unit, remembered in localStorage `units`. Static labels use `data-unit`. Power stays W and W/kg.
- `src/state.ts` — `live` ride state. Sensors write through `reading()`; a metric whose sensor is not connected or silent for 3 s reads 0 (never the last value).
- `src/fit.ts` — our own minimal FIT writer (protocol 2.0, little-endian): the messages and fields a ride needs, in plain units, scaled on write. To add a field, add its FIT profile number, base type and scale to `MESGS`. Checked 2026-11-02 against Garmin's decoder: same decoded messages as the SDK, file CRC valid.
- `src/recorder.ts` — 1 Hz samples holding each second's mean power/cadence and the ERG target (`tg`, absent on free steps), crash-safe in localStorage every 5 s + on unload (`ride-in-progress`, recover prompt on start screen if >60 s), FIT export (laps per workout step, `hrv` messages from the strap's RR intervals so Intervals.icu can compute DFA α1, `subSport: virtualActivity` → Intervals type `VirtualRide`)
- `src/actions.ts` — **rider actions**: the one list every input triggers (`pause`, `harder`, `easier`, `erg`, `skip`, `world`, `mute`, `end`, `keys`, `float`; each with label, keys, HUD button). Defined once in `main.ts` (`bindActions`); a remote (Zwift Click, a future phone remote) calls `press(id)`, which only acts during a ride. Presentation clickers already work: they send Page Up/Down (target ±10 W) and B/. (ERG); those keys sit in `more` (work, not listed in the popover). Keys work only during a ride, never while typing or with Cmd/Ctrl/Alt held. The ⌨ button / `?` shortcuts popover is built from this list (hidden on touch screens).
- `src/mini.ts` — **floating mini window** (Document Picture-in-Picture, Chrome/Edge only; `supported`): a small always-on-top card over every tab, for riding while watching something else. Big watts (red when off target: `hud.powerState()`, the same rule as the HUD's state chip) + target and rep on the left; time left, heart rate, step progress and next step on the right ("next" turns crust in the last 3 s). `main.ts` owns the mode: the ⧉ button / `F` toggles *Floating* (the window opens, `#hud.floating` hides the workout and data panels) ⇄ *In-app*; remembered in localStorage `hud-float`. In Floating mode the window opens on the ride-start click (Chrome needs a click: the demo's auto-start stays in-app); its ✕ switches back to In-app and turns the setting off; it closes when the ride ends. Updated from the tick, not rAF, so it keeps going while the app tab is hidden. Shortcuts work in it (`listenKeys`). Styles are the page's own, copied in; `.mini` in `style.css`. The window can't be see-through, and Chrome counts its title bar in the height it's asked for (asks 150 → ~94 px of content).
- `src/post.ts` — the "Post to" services (name, upload URL, hint shown after the click, `caption`): one line per service; the summary builds its buttons from it.
- `src/summary.ts` — summary charts: power over the ride against the target steps (SVG stretched to its box, axis labels in HTML) and time in each power zone (`zoneOf` in `workouts.ts`).
- `src/engine.ts` — **the ride engine, no DOM or Bluetooth**: workout clock (starts on the first pedal stroke, holds while the trainer is lost), targets (`watts()` + the −/+ offset), ERG/SIM switching, ERG death-spiral protection (releases ERG below 50 rpm for 3 s, re-engages at ≥60 rpm), `E` ride by feel, skip, pause, laps and step cues. Everything it drives comes in through `RideIO` (trainer erg/grade, recorder, route, beep/announce/banner), so it runs headless: bundle a script that imports it with `npx rolldown` and run it with `node`. Ride logic goes here, not in `main.ts`.
- `src/main.ts` — the screen around the engine: start screen, sensors → `live.power` (+ 3 s average), the HUD and cue line, summary and posting. **The engine is stepped by a 250 ms heartbeat from `src/clock.worker.ts`, with sub-stepping, not rAF** (Chrome pauses rAF in hidden tabs and slows a hidden tab's own timers to once a minute after 5 min; a worker's timers keep their pace; plain `setInterval` is the fallback). The screen wake lock is taken again when the tab comes back (Chrome drops it whenever the tab is hidden). Sample timestamps are forced to unique whole seconds. The cue line counts down 3-2-1 with the next step before each step change (beside the audio beep). The rider's legs spin at 85 rpm while there's power but no cadence source. The HUD sensor chip shows "＋ trainer / HR / cadence" for each unpaired sensor: clicking it opens the same picker as the start screen, mid-ride. Power = trainer whenever one was paired (0 while it's lost, no power-meter fallback); HUD shows a 3 s average. `beforeunload` asks before leaving a ride in progress. Effort cues stay quiet for 5 s after a resume or reconnect.
- `src/tokens.css` — design tokens, "Graphite" (charcoal panels at 80% opacity, one warm accent "crust", chalk for on-target/connected; Geist for UI, Geist Mono for labels/units, Doto dot-matrix for live metrics, self-hosted from `public/fonts/`): every colour, type size, spacing, radius, shadow and motion value as a CSS variable. No raw HUD values elsewhere (component sizes and the 3D world excepted); add a token instead. Canvas code reads them with `token('zone-3')` from `src/tokens.ts`.
- `src/style.css` — imports the tokens; documented components first (button secondary/primary/danger/icon, panel, mono label, cue (plain text + shadow, no box), live power + state chip, bars, stat tile, workout card, sensor chip, overlay card), then HUD layout and the responsive section (layout vars `--inset`, `--wo-w`, `--map-w`). Keep it distinct from commercial apps: no copied colours, layouts' styling or cue wording.
- `brand/` — dev-only brand reference at `/brand/` (not built, not linked): logo (`public/logo.svg`, also favicon + start screen), voice rules for cues and copy, tokens, components, contrast table. Follow its voice rules when writing cues.
- `public/_headers` — security headers (Netlify and Cloudflare Pages read it): CSP `script-src 'self'` (no inline scripts, nothing from other hosts; `style-src` allows inline for `style` attributes), `connect-src 'self'`, no framing, `Permissions-Policy: bluetooth=(self)`. Loading anything from another host = widen the CSP. Check a change on a deploy preview: CSP errors show in the console.
- **Settings for a hosted copy** (`.env.example`, defaulted to empty in `vite.config.ts`): `VITE_SITE_URL` (canonical + og tags in `index.html` via `%VITE_SITE_URL%`; those tags carry `vite-ignore` so an unset value builds), `VITE_IMPRESSUM_URL` / `VITE_PRIVACY_URL` (links in the start-screen foot, hidden when unset). Tips: `VITE_TIP_URL` (e.g. Ko-fi: "Support" in the foot + "Enjoyed the ride? Buy me a croissant" on the summary) and `VITE_TIP_WALLETS` (`network:address` pairs, comma-separated: one copy button each on the summary; with no clipboard it shows the address selected); unset = no tip link anywhere, and never on the start screen itself (no CTA). `VITE_UMAMI_SCRIPT` + `VITE_UMAMI_ID`: optional Umami analytics, added by the `umami` plugin in `vite.config.ts` at build only (script tag with `data-domains` = `VITE_SITE_URL`'s host and Do Not Track skipped, plus its origin in `script-src`/`connect-src` of `dist/_headers`); unset = no analytics, so the start-screen line says "no cookies", not "no tracking". Set in the host's build environment, never in the repo. `public/og.png` = link preview (the start screen at 1200×630: headless Chrome `--window-size=1200,630 --screenshot`).

## Posting rides
No uploads from the app (no API keys, no proxy). The summary offers Download .FIT plus a "Post to" row built from `src/post.ts` (Intervals.icu, Strava, Garmin Connect, TrainingPeaks): each downloads the .FIT, opens that site's upload page and shows its hint (`main.ts` `finish()`). Strava also gets a caption on the clipboard (workout, time, avg/NP power, TSS, avg HR, plus a line promoting the app with this page's host), since Strava leaves the description empty; photos can't be attached (no photo upload in Strava's API). Strava doesn't forward rides to Garmin or TrainingPeaks, so coached riders post to TrainingPeaks (drag onto today) or Garmin Connect (syncs on to TrainingPeaks). Any download clears the crash-saved ride. Done without a download asks first, then clears it too.

## URL flags
`?sim=1` simulated sensors · `?demo=1` the visitor **demo** = the simulator, entered when someone picks a workout with no sensor paired and accepts the prompt (`?demo=1&w=<workout id>` starts that ride at once, then the address goes back to `/`, so a reload or Back leaves the demo; `?demo=1` without `w` redirects to `/`). The ride is named "… (demo)"; ending, discarding or "New ride" goes back to `/` in normal mode, and a demo ride left in the crash save is dropped on the next normal visit. A rider with some sensor but no trainer still gets "Ride anyway?" · `?observe=1` read-only trainer (never takes control, e.g. to run beside another app) · `?debug=1` logs raw BLE packets and control-point writes (also in sim), exposes `window.gatt`.

## Hotkeys (ride)
`Space` pause · `+`/`-`, Page Up/Down, ↑/↓ target ±10 W · `E` (or B/.) ERG ⇄ ride by feel for this step · `M` mute cues · `F` floating mini window ⇄ in-app panels · `W` next world skin (~1 s fade, ride/recording/ERG keep going; last pick remembered per route in localStorage: `world-skin` for the valley, `world-skin-<route id>` for the others; also the globe button) · `?` shortcuts popover
